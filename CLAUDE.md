# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

**Graphersal** is an in-memory graph traversal engine in Rust modelled on Apache TinkerPop Gremlin. This file is the single source of agent guidance (`AGENTS.md` only points here). When it disagrees with the code, the code wins. Tell the user so the stale section gets fixed.

## Workspace

- `crates/graphersal`: the core library. Almost all work happens here.
- `crates/graphersal-cli`: the REPL (`graphersal>`, `src/repl.rs`: `/` commands, Tab completion and `/help <name>` read `graphersal_session::views::completion_entries`/`token_values`, the playground's catalogue, never a CLI list; `--repl` runs it on a piped stdin), a one-shot, scriptable query runner, and `--server`: the DEV server (feature `dev-server`, on by default; `tiny_http`, loopback only: 127.0.0.1 plus `[::1]` on the same port when available, unstable) that serves the playground UI embedded in the binary (`build.rs` generates an `include_bytes!` table from `ui/`, a symbolic link to `../../playground` that `cargo package` follows; entries `index.html`, `css/`, `js/`, `assets/`, `reset/`; a file of `--ui-dir`, default `./playground` when it exists, wins over the embedded copy; `src/server/ui.rs`, whose test fails when the embedded set differs from `playground/`) with this process as the engine (`src/server/`: `mod.rs` HTTP API and the change feed `GET /api/changes`, `store.rs` the `/api/store*` endpoints, `layout.rs` the engine force layout `/api/layout*` (slices; Stop ends a running one), `mcp.rs` the MCP endpoint; book page `persistence/dev_server.md`); the CLI limit flags become the session's `graphersal_session::SessionPresets` (`server::session_presets`), display flags are refused with `--server`. At start the server prints on stderr the load time and the graph's statistics (`src/server/start_stats.rs`, from `Session::statistics`, the Statistics tab's data; stdout keeps only the address line). `--server`, `graphersal store` and every mode on a `--graph <store>` install `src/log.rs`, a minimal stderr `tracing` subscriber (no `tracing-subscriber`; `GRAPHERSAL_LOG`, default `warn`; never stdout). "Save to file" (`POST /api/save`) writes the graph back to its `--graph` file and, with `--schema FILE`, the schema back to that file (both atomic); without it a GraphML/GraphSON save of a graph with a schema answers a `warning`. `--mcp [--mcp-read-only] [--mcp-token] [--mcp-query-tools]` adds `POST /mcp`: hand-written MCP Streamable HTTP (initialize-based revisions, JSON answers, no SSE, no `rmcp`/tokio) whose tools wrap session methods and queue on the session thread like browser calls. MCP works with the graph only: `query`, the schema tools, `statistics`, `graph_info`, saved queries, compression rules and property indexes; NO persistence tools (the Store menu and `/api/store*` are the user's); a read-only view the browser opens is server-wide, `graph_info` and every tool error then carry a `note` ("the served state is a read-only view at commit N ..."). Read-only runs `query` under `graphersal_session::read_only_authorizer`. Saved queries: tools `list_saved_queries`/`run_saved_query` (also read-only), resource `graphersal://saved-queries`, the instructions point to them; `--mcp-query-tools` lists each saved query as its own tool (`tools/list` follows the catalog, `listChanged: false`). Compression rules: tools `list_compressions` (also read-only), `define_compression`/`drop_compression`/`recompress` (refused read-only); property indexes: `list_indexes` (also read-only), `create_index`/`drop_index` (refused read-only); the read-only authorizer denies every catalog write. `/api/queries*` are the saved-query endpoints, `/api/compression*` the compression-rule ones, `/api/indexes*` the property-index ones, `/api/catalog/export|load` the ONE catalog file (every kind). Every session job that moves the served graph's commit position is recorded in the change feed with its client (`X-Graphersal-Client` of a page, or `mcp`); the playground polls it (`js/change-feed.js`) and reloads on changes it did not make. Verify MCP changes end to end with curl as a client (initialize -> tools/list -> tools/call). `--ai FILE` (feature `ai`, default on, needs `--server`, not `--mcp`; EXPERIMENTAL) is the AI Chat's LLM client in `src/ai/`: `config.rs` (the strict JSON file, checked at server start: provider `openai`/`anthropic`, model, key from the variable `api_key_env` names, limits; the key is never logged or shown), `client.rs` (provider-neutral `Conversation` -> `Client::complete` -> `AssistantTurn`, `AiError` with `help()`), the adapters `openai.rs` (Chat Completions + tools; the answer's message kept as `raw`, tool-call fields it does not rebuild such as Gemini's thought-signature `extra_content` copied back by id, message-level only `extra_content`, never `reasoning_content`) and `anthropic.rs` (Messages + tool use, `cache_control` on the system prefix, assistant content replayed unchanged) over `ureq` + rustls (synchronous, no tokio); tested against a local `tiny_http` mock with recorded fixtures (`src/ai/fixtures/`), never a real provider. The agent loop is `src/server/ai.rs`: conversations in memory (random 128-bit ids, owned by the creating `X-Graphersal-Client`, `403` for others), one turn at a time each (`409`), each turn on its own thread; tool calls go through `mcp::tool_listings`/`mcp::call_tool` (the MCP handler uses the same two; `ToolCaller` carries read-only, the change-feed client `ai` + the conversation id as the feed's `detail`, and the turn's own `CancelToken`, run via `Session::execute_with_cancel`, so Stop cancels only that conversation's query, never the session-wide token); the system prompt = MCP instructions + agent rules (tool results are untrusted data, queries in ```` ```graphersal ```` blocks, GFM tables) + the DSL reference + a graph summary taken at the first turn (kept fixed for the prompt cache); endpoints `/api/ai/conversations[/<id>[/messages|/events?after=N|/stop]]`, `GET /api/info` `ai`. `graphersal` feature flags. All are off by default and must stay strictly additive:
- `io`: the two graph file formats, neither carries the schema. **GraphSON 3.0** (`io/graphson.rs`, the primary exchange format for Gremlin users; dependency-free, on `physical::read_json`): import reads the line form (one vertex per line) and the wrapped form `{"vertices": [...]}`, 3.0/2.0 typed and untyped 1.0, leniently: typed values map to logical types (`g:Int32` -> `int64`, `g:UUID` -> `uuid`, `g:List`/`g:Set` -> `array`, `g:Map` -> `object`, the `java.time` types to the temporal types: `g:Date`/`g:Timestamp`/`gx:Instant`/`gx:OffsetDateTime`/`gx:ZonedDateTime` (zone id dropped, reported) -> `datetime`, `gx:LocalDate`/`gx:LocalDateTime`/`gx:LocalTime` -> `date`/`localdatetime`/`time`, `gx:Duration`/`gx:Period` -> `duration`; table in the `io/graphson.rs` module doc); every type we cannot hold (`gx:Year`, `gx:MonthDay`, `gx:OffsetTime`, ...) is SKIPPED and listed in the returned `ImportReport`, never converted; ids become strings, `"A::B"` labels split, multi-valued properties become one array, meta-properties the reserved `_meta` object; bounded by `GraphSONImport::max_text_bytes` per line/document and the value depth. Export writes the line form with typed values (TinkerGraph loads it), `_meta` back as meta-properties when it has the import shape. API: `GraphSource::from_graphson(_reader)`, `GraphSONImport::load(_file)` (with the report), `GraphImport::import_graphson(_reader)` (one unit), `GraphExport::export_graphson(_writer)`, Rhai `import_graphson`/`importGraphson`, `export_graphson`/`exportGraphson`; `from_file` picks GraphSON for `.json`/`.jsonl`/`.graphson`. Docs: `book/src/users_guide/graphson.md`. **GraphML** via `quick-xml`. GraphML values go through the physical codec; logical types are restored on import only from the TARGET graph's stored schema (set the schema first, then import): a declared `uuid` or temporal format from its canonical text, a declared `array`/`object` from its JSON text (`physical::read_json`, no `serde` needed); undeclared text stays a string. GraphML never carries the schema (no embedding; graph-level `<data>` is ignored): the schema travels separately as its own JSON (the playground's Save graph downloads both files; its "Load from file" dialog takes a graph file plus an optional schema file, set on the new empty graph before the import: a loaded graph file never keeps the previous graph's schema).
- `script`: the Rhai DSL.
- `display`: tables via `tabled`. Never pull `tabled` into `script` or the engine.
- `serde`: `ChangeSet` serialization, `Serialize`/`Deserialize` of `GraphSchema` (the schema format itself, `from_json`/`to_json`, needs no feature) and the `json` visualizer. It is not a graph file format.
- `persist`: the native, lossless binary format over streams (`persist/`; the normative spec is the PUBLIC book page `book/src/persistence/format.md`, cited in code comments as "format spec N" with its section numbers; keep it in sync with any byte-level change): packed snapshots, the `Journal` write-ahead hook, marks, recovery (see **Persistence** below); brings `lz4_flex` and `crc32c`. `persist-zstd` adds zstd chunks (`ruzstd`). Both build for wasm32. `persist` also brings the **Store** (`persist/store/`, one directory = one graph) over the EXPERIMENTAL `persist::StoreDir` trait (`persist/dir.rs`): `FsDir` (native; OS lock through `fd-lock`), `SingleFileDir` (native: the whole store in one log-structured `.gstore` file, format spec 14; free disk space through `rustix` `statvfs` on Unix) and `MemDir` (in memory, every target incl. wasm32, where the playground keeps every loaded graph as a store); `persist-zip` adds ZIP backups (own stored+zip64 writer/reader, no dependency). The acceptance feature set is `script,io,display,serde,persist` (the surface snapshot is taken with it; without `persist` the snapshot functions are filtered out of the comparison).
- `alloc-tracking`: exact, allocator-level per-step memory figures for `.profile_with(ProfileType::Memory)` (`MemorySource::Tracked`), via `alloc_tracking::TrackingAllocator`, a `GlobalAlloc` wrapper the *binary* installs as its own `#[global_allocator]` (a library crate cannot do this for a consumer). Off by default for `graphersal` itself, like every feature above — but unlike them, `graphersal-cli`, `graphersal-wasm` and `py-graphersal` build with it **on by default** and install the allocator (the CLI in its `main.rs`, the wasm module in its `lib.rs`, wasm32 only: single-threaded, so the thread-local counters are the module's; the Python extension in its `lib.rs`, a `cdylib`: it counts the extension's Rust heap only, never Python objects, so with `memory_limit="auto"` the headroom must cover the Python side), trading a small, constant, always-on per-allocation cost (`thread_local` counter increments plus one relaxed global atomic, `alloc_tracking::global_live_bytes`, which the memory budget reads) for exact numbers in the reference binaries this project ships. Without it, `.profile_with(ProfileType::Memory)`'s `Mem` column reports `MemorySource::Estimated` — a `size_of`/capacity-based estimate, always available, no allocator hook. A bare `.profile()` (no `ProfileType` argument) never collects memory data at all, regardless of this feature — no step carries a `memory` section — so it always pays for a plain timing table only.
- `model2vec`: the embedder `vector::Model2Vec` (`value/vector/embed/model2vec.rs`, book `users_guide/vectors.md` "Model2Vec models" and `getting_started/embeddings.md` "Real models: Model2Vec"): a Model2Vec static embedding model loaded from a LOCAL directory only (never the network) through `model2vec-rs` (no default features: no `hf-hub`/`ureq` 2) + `tokenizers` (`fancy-regex`, pure Rust: no `cc`/C/C++, keep it so) + `safetensors`; deps are `cfg(not(target_arch = "wasm32"))` and the module is `cfg(all(feature = "model2vec", not(target_arch = "wasm32")))`, never enabled for wasm32/`graphersal-wasm`. `Model2Vec::load(name, dir)` / `Model2Vec::options().with_max_tokens(..).with_normalize(..).with_max_batch(..).load(..)`; layouts as `model2vec-rs` (`config.json` + `tokenizer.json` + `model.safetensors`, or the sentence-transformers ones); the load checks the safetensors shape and every vocabulary id (via `mapping`) against the matrix rows, so no lookup goes out of range; every call into `model2vec-rs` runs under `catch_unwind` (its `encode` has `expect("tokenization failed")`) -> `EmbedError::Failed`; load failures `EmbedError::Unavailable` with the `graphersal embed-model download <repo>` hint; an all-zero mean (no known token) is `NoFeatures`. Info: dimension of the model, F32, cosine, `max_batch` 256, `deterministic: false` (bits depend on the `model2vec-rs`/`tokenizers` versions), `local`. Model identity `model2vec/<repo>@<12 hex>` (`<repo>` from the manifest `graphersal-embed-model.json`, `Model2Vec::MANIFEST_FILE`) or `model2vec@<12 hex>`: SHA-256 of `model2vec-identity/1\n` + one line `<role> <size> <sha256>\n` per file (roles config/tokenizer/model), never a path (`Model2Vec::model_identity(dir)`); a normalize override that differs from the config adds `?normalize=..`. Own SHA-256 in `embed/sha256.rs` (no SHA crate in the library's tree). It uses `std::fs` (native only, like `FsDir`). Tests `tests/all/model2vec_tests.rs` (a tiny synthetic model written by the test; `a_real_potion_model` is `#[ignore]`, needs `GRAPHERSAL_EMBED_MODELS`).

The workspace is on Rust edition 2024 (MSRV 1.88). Doctests are merged into one binary per crate: a doctest must not rely on process-global state, env vars or `#[global_allocator]`; mark one that must stay separate with `standalone_crate`.

### Observe queries with `graphersal` instead of guessing

Run a traversal to see what it actually returns. Don't reason about what it should return.
```bash
cargo build -p graphersal-cli                                   # rebuild after touching graphersal
target/debug/graphersal -e 'g.v().has_label("person").values("name").to_list()'
target/debug/graphersal -e 'g.v().has_label("person").count().profile()'   # optimized physical plan
echo 'g.v().values("age").max().next();' | target/debug/graphersal --in --graph modern
target/debug/graphersal -e 'let xs = g.v().to_list()' -e 'xs.len()'         # -e repeats and shares one scope
```
- `--graph` takes `modern` (the default), `empty`, `large` (about 110k elements), or a path to a GraphSON (`.json`/`.jsonl`/`.graphson`; skipped data is a `note:` on stderr) or GraphML (`.xml`/`.graphml`) file. `--schema FILE [--schema-mode MODE]` sets that schema on the new empty graph first and imports the file against it as one unit (a sample graph gets it applied; a violation exits `1`; refused with a Store or `.gsnap`; the server keeps the path as `schema_source`).
- `--format <fmt>` presets the visualizer.
- Display is bounded, data never: a displayed result (a traversal without a terminal, a final list/map, a final graph value as its `{vertices, edges}` listing, an explicit `to_table()`/`to_json()`/...) shows at most 100 rows and 100 nested items. `--max-rows <N>`, `--max-items <N>` and `--no-limit` change that (REPL: `/set max-rows <N>`, `/set max-items <N>`, `/set no-limit`); one call overrides it with `#{max_rows: n}` / `#{no_limit: true}`. `to_list()`/`next()`/variables are never cut. See `book/src/users_guide/displaying_results.md`.
- stdout carries only the result. stderr carries only the diagnostic and the truncation notice (`… showing the first 100 rows; more exist. ...`), which leaves the exit code at `0`.
- Exit codes: `0` ok, `1` script failed, `2` invalid invocation, `141` stdout closed early (`| head`). The CLI never uses `print!`/`eprintln!` (denied by clippy, they panic on a closed pipe): output goes through `out!`/`outln!`/`errln!` of `graphersal-cli/src/out.rs`.
- `graphersal` builds with exact per-step memory tracking (`alloc-tracking`, on by default): `.profile_with(ProfileType::Memory)`'s `Mem`/`Retained`/`Allocs` columns report `MemorySource::Tracked` bytes, not estimates. A bare `.profile()` shows timing only. `g.memory_usage()` reports a graph's own footprint directly.

Use it to:
- verify a new step or DSL binding end to end;
- confirm a pushdown with `.profile()`;
- copy real `help()` text into tests;
- reproduce a user's query.

The CLI does not replace tests. Behaviour you rely on still needs a test in `crates/graphersal/tests/`.

### TinkerPop conformance suite

`--test tinkerpop_features` runs the vendored Apache TinkerPop 3.8.2 Gherkin scenarios
(`crates/graphersal/tests/tinkerpop/features/`) through the Rhai DSL and gates them against the ratchet
baseline `crates/graphersal/tests/tinkerpop/baseline.toml`. The harness (parser, translator, runner,
classifier, report) lives in `crates/graphersal/tests/tinkerpop/harness/`; see
`crates/graphersal/tests/tinkerpop/README.md` and `book/src/for_developers/tinkerpop_compliance.md`.
`target/tinkerpop-report.md` ranks the failures (missing steps/tokens, wrong results); use it as the fix
backlog.
`GRAPHERSAL_TEST_STORAGE=forwarding` runs the same suite with every dataset on `Graph<Forwarding>` (the proof
storage of `graphersal-storage-tests`, `harness/storage.rs`; the harness holds `Arc<dyn AnyGraph>` in both modes):
same baseline and page, no class change allowed, never rewrites them (an update is refused), report
`target/tinkerpop-report-forwarding.md`; not in CI (run it locally before a release).

- **Principle (user decision):** an unimplemented step is fine; an implemented step must follow the TinkerPop specification (the vendored feature files win over assumptions) unless a user decision says otherwise. The error-message *text* of TinkerPop is not chased.
- **Scope and headline:** the denominator is the compatibility scope (the live numbers are in the generated blocks of `book/src/for_developers/tinkerpop_compliance.md` and in the report; do not repeat counts here). Two families are excluded from it: scenarios using `withStrategies(...)`/`withoutStrategies(...)` (Graphersal will get its own execution-metadata mechanism) and the *deliberate incompatibilities*, an explicit reviewed table of scenario ids grouped by reason (`INCOMPATIBILITIES` in `tests/tinkerpop/harness/scope.rs`; ids only, never tags). The headline separates **Unsupported** (classes `missing`/`translate`: not implemented) from **Wrong behaviour of supported steps** (`runtime`, `wrong_result`, `wrong_error`, `timeout`, `panic`); the second must stay 0. To re-include a scenario, remove its id from the table and regenerate.
- **Compliance page:** the generated blocks of `book/src/for_developers/tinkerpop_compliance.md` (between `<!-- tinkerpop:begin NAME -->` and `<!-- tinkerpop:end NAME -->`) are compared on every run and the test **fails on drift**; `TINKERPOP_UPDATE_BASELINE=1` rewrites them together with the baseline (rule 19).
- **Deviations:** `book/src/for_developers/tinkerpop_deviations.md` is the single list of deliberate deviations and known gaps (rule 18).
- **Float normalization:** the harness (not the engine) compares float64 results within 1 ulp (`compare::floats_within_one_ulp`); nothing else is normalized.

## Architecture (graphersal)

**Storage.** `TraversalGraph` (`graph/mod.rs`) holds a petgraph `StableGraph` plus property maps and indexes (`graph/index.rs`); a shared graph is `Graph<S = TraversalGraph>` (`graph/shared.rs`), a lock newtype over `parking_lot::RwLock<S>` whose `read()`/`write()`/`try_write()` guards (`GraphRead`/`GraphWrite`) deref to `S` (`Graph::new(x)`, `&mut *g.write()`; no `parking_lot` type in the API). `AnyGraph` (`graph/any_graph.rs`, `graphersal::storage`, EXPERIMENTAL) is the sealed dyn boundary the front ends hold (`Arc<dyn AnyGraph>`, via `IntoAnyGraph`): blanket for every `Graph<S>` with `S: Default + Send + Sync + 'static`, one coarse operation per method (identity/capabilities/statistics/memory, the seven schema methods, catalog incl. `set_definitions` in one unit, `mark`, io, `write_snapshot` (see `Graph::new_persistent` under **Persistence**), and with `script` the plan group `run_plan`/`run_unit`); the script layer and, through `SessionGraph`, the session hold it (see **Custom storages**). petgraph is not in the public API. The pipeline is generic over the `GraphStorage` trait (`graph/storage.rs`, EXPERIMENTAL in 0.1.x; its trait-level rustdoc is the implementer's guide), implemented for `TraversalGraph`, its `&mut`/`Box`/`Arc` wrappers, the blanket read-only view `&G` of every storage (`&` and a shared `Arc` are read-only and claim no capabilities) and a test-only `MockStorage`; `graphersal-storage-tests` is its conformance suite. **Handles:** `VertexId`/`EdgeId` of `TraversalGraph` are the opaque generational `VertexHandle`/`EdgeHandle` (`graph/handle.rs`: slot + `NonZeroU32` generation, no public constructor; the generation lives in the weight, edges store their endpoints' generations). A handle to a removed element never aliases another one: reads through it are "removed" (`contains_vertex`/`contains_edge` false, properties absent, adjacency empty, filters drop it), `id()`/`label()`/materialization/writes fail with `GraphError::ElementRemoved` (deviation, `book/src/users_guide/dropping_elements.md`), a second drop is a no-op. A new handle-taking method validates through `resolve_vertex`/`resolve_edge` or `vertex_weight(_mut)`/`edge_weight(_mut)`. Steps carry lazy handles (`TraverserValue::Vertex`/`Edge`, `VertexProperty`/`EdgeProperty`, `Record { keys: Arc<..>, values }`), not materialized properties; `size_of::<TraverserValue>()` stays 64. A vertex carries a label *set* (`Vec<CompactString>`, ordered and deduplicated; empty means unlabeled), not a single optional label — the first label is the primary one that `vertex_label()`/`label()`/`elementMap()` keep returning single-valued, matching TinkerPop, while `vertex_labels()`/`labels()` expose the full set as foundation for a future Cypher/GQL front end's `(n:A:B)`. Edges stay single-labeled throughout; `GraphStorage::set_edge_label` changes an edge's label (checked under the new label, nothing coerced; `UndoEntry::EdgeLabel`, `Mutation::SetEdgeLabel`, WAL op 11). **Insert vs. add:** `GraphStorage::insert_vertex`/`insert_edge` are the required primitive (store exactly what they are given, coercing and validating; imports, change sets, replay/recovery, loads and copies call them, so they never generate a value); `add_vertex`/`add_edge` (never override them) create the way a query does: `add_vertex_with`/`add_edge_with(.., &CreateContext)`, the override point, apply the schema's create-time defaults and then call `insert_*` (conformance `add_applies_schema_defaults_insert_does_not`; `Mutation::AddVertex`/`AddEdge` keep their names).

**Custom storages.** A host's own `GraphStorage` (+ `Default + Send + Sync + 'static`; `PersistentStorage` to be stored) runs under every generic front end; book `for_developers/custom_storage.md` (what to implement, how to plug in, what stays `TraversalGraph`-only, the complete host example `crates/graphersal-session/tests/custom_storage_example.rs` included into it by mdBook anchors). The engine is monomorphised per storage; above it one dyn boundary per layer, one virtual call per operation: `AnyGraph` (script layer, saved queries; sealed, blanket for `Graph<S>`), `SessionGraph`/`SessionStore`/`GraphFactory` (session; `Session::with_storage(Arc::new(StorageKind::<S>::persistent()))`), the crate-internal `StoreGraph` under `Store<S>` (`create_in`/`open_in`). Generic over `S`: units and `Transactional`, change capture through the public `ChangeSet::builder`/`Mutation` constructors and an embedded `CommitHooks`, snapshots, replay, recovery, the Store, the session helpers. `TraversalGraph`-only: script scratch graphs (`GraphSource::*`, `__`, `_g`, `subgraph`/`cap`/`toGraph`), a `withSideEffect` subgraph target (foreign: `Unsupported`), compressed properties (rules kept in the catalog, `recompress` `Unsupported`), the undo log and its capture, the merge checkpoint's/salvage's/repair's working graphs, and the shipped front ends (CLI, dev server, MCP, Python, wasm). An operation a storage does not implement is `GraphError::Unsupported { operation }` (its help names the operation and points to the storage's docs and capabilities). The proof is `Forwarding` (`graphersal-storage-tests`): `foreign_storage_tests.rs` (DSL differential), `generic_persist_tests.rs`, `foreign_store_tests.rs`, the session's `storage/tests.rs`, the example, TinkerPop with `GRAPHERSAL_TEST_STORAGE=forwarding` (the first ones run in every `cargo test`, the TinkerPop run on `Forwarding` locally before a release).

**Units (undo log).** `GraphStorage::begin_unit() -> UnitMark` / `commit_unit(mark) -> Result` / `rollback_unit(mark, &RollbackReason)` bound a unit of atomicity; units nest (an inner unit is a savepoint). The defaults are no-ops (a non-atomic storage); `&mut`/`Box`/a solely owned `Arc` forward. `TraversalGraph` implements them with a private undo log (`graph/undo.rs`): while a unit is open every mutating method records its inverse (string ids and element images, never handles; old property value with its position; old label set; old schema), and a rollback replays it in reverse through the raw helpers (`insert_vertex_raw`, `remove_vertex_raw`, `insert_edge_raw`, `remove_edge_at`), restoring structure, indexes, statistics and the schema (not iteration order; restored elements get new handles; auto-id sequences are never rolled back: ids are never reused, gaps are fine). Every traversal is one unit (implicit auto-commit): `run()` and every terminal (`to_list`, `next`, `iterate` (results discarded, never materialized), visualizers, `execute_items`, `to_graph`) run inside `GraphTraversalSource::atomically`, so a failing traversal (step, schema, limit, timeout, materialization) leaves nothing (deviation, `book/src/users_guide/transactions.md`). Also one unit each: `set_schema` and a catalog change (`set_definition`/`remove_definition`) outside a unit, a GraphML or GraphSON import into a live graph (`import_graphml*`, `GraphMLImport::import_reader`, `import_graphson*`, `GraphSONImport::import_reader`), `apply_change_set`. Loading a graph nobody sees yet (`GraphSource::from_graphml(_reader)`, `from_graphson(_reader)`, `GraphSONImport::load`, `TraversalGraph::replay`) runs outside units (`load_outside_units`: unlogged, uncaptured, no hooks); direct trait calls outside a unit are not recorded either. Explicit units (`graph/transaction.rs`) are the blanket extension trait `Transactional` (every `GraphStorage`; prelude and `graphersal::storage`): `transaction(|g| ..)` / `transaction_with(CommitMetadata, ..)` (closure, no guard object to forget; a panic in it rolls back; `E: From<GraphError>` carries a veto; nested = savepoint, nested metadata merged into the enclosing one through `GraphStorage::set_unit_metadata`, called before the commit, the outer unit's wins), `dry_run(|g| ..) -> (T, ChangeSet)` (always rolled back through `GraphStorage::discard_unit`: no hooks, `commit_seq` 0; needs `change_capture`, the default rolls back and returns `Unsupported`). `GraphStorage::mark(name)` (default `MarkUnavailable`, `&G` `Unsupported`) is `TraversalGraph`'s journal-slot mark. A mutation outside a unit records nothing (conformance `mutation_outside_unit_records_nothing`). `GraphStorage::unit_changes(mark) -> UnitChanges { data, schema, definitions }` (default nothing) is part of the `atomic` contract and makes `Execution::mutated()`/`changes()` (Rhai `r.mutated`/`r.changes`) right for a run nested in an outer unit. Rhai whole-script unit: host option `script::eval_value_atomic` (the graph moves into a private lock while the shared write lock is held; a returned traversal is retargeted, a returned closure/`FnPtr` fails with `ScriptError::ReturnedClosure` and rolls back); the playground runs every script as one unit (commit iff `ok`), the CLI and Python keep the per-traversal default. A panic unwinding through any unit rolls it back first and then continues (`graph::storage::close_on_unwind`: `run()`, `atomically`, `execute_items`, `transaction`/`dry_run`, the whole-script units, `apply_change_set`, GraphML and GraphSON import, `set_schema`; defence in depth, panics stay bugs per rule 1); a new unit opener uses it too. The commit is covered once in `commit_undo_unit` (not per opener): a panic while deriving the change set or in a `before_commit` hook rolls the unit back, sends `after_rollback` (a second panic there dropped) and resumes; a panic in `after_commit` leaves the unit committed. A new mutating `GraphStorage` method of `TraversalGraph` must record an `UndoEntry` only when it changed something, keep the statistics exact, and get a case in `graph/capture.rs`.

**Change capture.** `ChangeSet` / `Mutation` (`graph/change.rs`, public, `#[non_exhaustive]`, built outside the graph with the constructors below; `compact()`, serde behind `serde`) describe one committed unit: `commit_seq`, `committed_at` (i64 µs since the epoch via `web_time::SystemTime`, monotonic per graph: `max(now, previous)`, also taken without hooks, `last_committed_at()`; `0` with `commit_seq` 0 for a dry run), the auto-id sequences `node_sequence`/`edge_sequence` AFTER the unit (on every ChangeSet), `CommitMetadata`, the mutations in execution order with before and after values; cascaded `DropEdge`s precede their `DropVertex`; a jpath write is a `SetProperty` of the top-level key; a schema change is a `SetSchema` in the same stream. Built at the outermost commit, only while a commit hook is registered, by `TraversalGraph::derive_mutations_since` (`graph/capture.rs`): a backwards walk of the undo log over a shadow of the touched elements yields the after-values, so nothing is recorded during the mutations and nothing is paid without hooks. Hooks (`graph/hooks.rs`, `CommitHook`: `before_commit` may veto -> rollback + `GraphError::CommitRejected { hook, source }` (its help is generic unless the source is a `HookRefusal { message, help }` or a `PersistError`, which bring their own), `after_commit`, `after_rollback(&RollbackReason)`; `GraphStorage::register_commit_hook`, default `GraphError::Unsupported`; cannot be removed) run in registration order, in `commit_seq` order, and get the `ChangeSet` only, never the graph; units that change nothing emit nothing, except a unit that only RAISED an id sequence (`raise_id_sequences`, e.g. applying a change set whose mutations were compacted away): a sequence-only commit (takes a `commit_seq`, a `ChangeSet` without mutations carrying the raised sequences, hooks/veto, journaled as a Commit record with 0 mutations; `Execution::mutated()` false). Outside the graph a `ChangeSet` is built with `ChangeSet::builder(commit_seq, committed_at)` (`ChangeSetBuilder`, `build()` checks cheaply: `GraphError::InvalidChangeSet`) and one constructor per `Mutation` kind (`Mutation::add_vertex`, ...); a foreign storage embeds the public `CommitHooks` (`graph/hooks.rs`: `register`, `before_commit` -> `CommitRejected`, `after_commit`, `after_rollback`, `mark`, `set_journal(JournalSlot)`; the ordering contract lives there once; no reusable undo-log component). `GraphStorage::last_commit_seq()` (advanced by every outermost commit of a non-empty unit, with or without hooks) plus an export under one read lock is a snapshot with position; `TraversalGraph::with_last_commit_seq(n)` continues the numbering after a rebuild. `GraphStorage::apply_change_set` (default impl over the trait's mutating methods in one unit: captured, vetoable) applies to a live graph and then raises the auto-id sequences to the change set's (`GraphStorage::raise_id_sequences`, default no-op, `max`, never lowered); `TraversalGraph::replay(self, &ChangeSet)` rebuilds an unpublished one without hooks and raises `commit_seq`, the commit time and both id sequences to the change set's (never lowers), so an auto id of a dropped or rolled-back element is never reused. Counters never wrap: `commit_seq` and the id sequences use checked increments, overflow is `GraphError::SequenceOverflow` (commit: the unit is rolled back, hooks get `after_rollback`). Serde of a `ChangeSet` tags non-JSON logical types per value (`{"@type":"g:UUID","@value":..}`, the temporal types as `gx:OffsetDateTime`/`gx:LocalDate`/`gx:LocalDateTime`/`gx:LocalTime`/`gx:Duration`/`gx:Period`/`graphersal:Interval` with their canonical text, user objects with an `"@type"` key escaped as `graphersal:Object`, strict reading; `value/physical.rs` `Tagged`/`TaggedOwned`); GraphML and the rest of the codec stay untagged. `StorageCapabilities` (`graph/capabilities.rs`, `GraphStorage::capabilities()`, facts not permissions; `TraversalGraph`: `atomic`, `change_capture`, `writable`): `change_capture` requires `atomic` (a storage that cannot roll back cannot honour a veto; debug assertion in `GraphTraversalSource::new`); `graphersal-storage-tests`' `extension` items are conditional on it. Docs: `book/src/users_guide/transactions.md`.

**Persistence** (feature `persist`, `persist/`, book part "Persistence" `book/src/persistence/`: overview, the Store pages, `store_cli.md` (every `graphersal store` command; update it with `store_cmd.rs`), `dev_server.md`, `format.md` (the spec), `faq.md`; the user-facing command list is `book/src/users_guide/command_cheat_sheet.md`). `codec.rs` (fixed LE ints, LEB128, the tagged value encoding shared by segments and journal, CRC-32C, chunk compression with size bounds), `segment.rs` (`ChunkEncoder`: id-sorted elements into self-contained chunks with their own string table, handed out one at a time; **Diagnostics.** `graph.memory_usage() -> Option<MemoryStats>` (`graph/memory.rs`) is a `GraphStorage` trait method, not a `TraversalGraph`-only inherent one (default `None`; `TraversalGraph` overrides with `Some`) — an on-demand, opt-in-by-call snapshot of a graph's own footprint (`structure_bytes`/`index_bytes`/`property_bytes`), entirely separate from traversal execution. `.profile()` is memory-blind by default: `GraphTraversalSource::profile()` is a thin wrapper for `.profile_with(ProfileType::none())`, and `.profile_with(ProfileType::Memory)` is what turns memory collection on. With it on, every step's `Metrics` carries a `memory: Option<MemoryMetrics>` section (`bytes_materialized`/`bytes_retained`/`alloc_count`/`source`): `MemorySource::Estimated` (default, `size_of`/capacity-based, computed inside the existing `is_profile` gate, zero cost when profiling isn't used) or `MemorySource::Tracked` (exact, via the `alloc-tracking` feature's `TrackingAllocator`, a `GlobalAlloc` wrapper the binary installs). With it off (a bare `.profile()`), no step has a `memory` section and no allocator/estimation work runs at all. Only steps that self-report `materializes() == true` (`group()`/`fold()`/`sum()`/`mean()`/`median()`/`path()`/`element_map()`) get a non-zero estimate; every lazy pass-through step costs nothing to profile.

**Schema.** One format everywhere (Rust, Rhai, Python, playground): our envelope outside, a strict subset of JSON Schema 2020-12 inside. Envelope `{"$schema": "https://graphersal.dev/schema/v1" (SCHEMA_FORMAT_URL, optional), "meta": {free, stored, never interpreted}, "mode": "none"|"open"|"closed" (default none), "vertices": {label: {"schema": <object node>}}, "edges": {label: {"connections": [{"from", "to"}], "schema": ..}}}`; a label schema is a `{"type": "object", ...}` node (`$defs`/`$schema`/`$id` only at its root). Unknown keys/keywords are errors at every level (`SchemaError::InvalidSchema { path (JSON Pointer), reason, hint }`); the empty schema is no schema (`set_schema({})` clears). The meta-schema is `graph/schema/graphersal-schema-v1.json` (`META_SCHEMA_JSON`). `graph/schema/` covers:
- the node `PropertySchema` (`node.rs`): `type` (string or array; `integer` = `int64` exact, `number` = `float64`, `string`+`format`: `uuid` = `uuid`, `date-time`/`date`/`local-date-time`/`time`/`duration` = the temporal types (`SchemaFormat`); `array`+`format: vector` with `element`/`dimension`/`metric`/`embedder` = a vector (`VectorSchema`, coerces a list or another element kind on write, no `items` beside it; `embedder` = the model identity `EmbedderInfo.model` that produced the vectors, top-level properties only (`check_defaults`), written and checked by `embed_property`, read by text queries, never checked by a plain write, never inferred, `diff` kind `embedder_changed`: adding compatible, changing/removing not); no other `format`), `items`, `properties`, `required`, `additionalProperties` (bool only, no map-of-T), `anyOf`; constraints `minimum`/`maximum`/`exclusive*`/`minLength`/`maxLength`/`pattern`/`minItems`/`maxItems`/`enum`/`const`, for temporal formats `formatMinimum`/`formatMaximum`/`formatExclusiveMinimum`/`formatExclusiveMaximum` (a keyword must fit the declared type; it applies only to values of its kind); annotations `title`/`description`/`$comment`/`examples`/`deprecated`, the create-time keywords `default`/`defaultFunction` (`uuidv4`/`uuidv7`/`now`/`today`, `DefaultFunction`). Local `$ref: "#/$defs/X"` is inlined at load (cycles rejected). Parser/printer `parse.rs` (`GraphSchema::from_json`/`from_value`/`to_value`/`to_json`, canonical keyword order); builders on `PropertySchema` and `GraphSchema` (`with_mode`, `with_vertex`, ...). **`default`/`defaultFunction` are create-time defaults** (SQL `DEFAULT`; `defaults.rs`, rules in the `Annotations` rustdoc): applied only when an element is CREATED (`add_v`/`add_e`, `mergeV`/`mergeE` on create, `GraphStorage::add_vertex`/`add_edge`), only for a label's TOP-LEVEL properties the element lacks, only in modes `open`/`closed`, before coercion and validation (so they satisfy `required`); never on read, never re-applied when the schema changes, no backfill; `default: null` is never stored; imports, change sets, replay/recovery, loads and the primitive `insert_vertex`/`insert_edge` never apply them (they store exactly what they carry). `uuidv4`/`uuidv7` give a new value per element, `now`/`today` ONE value per unit: its start (`GraphStorage::unit_started_at`, monotonic per graph), unless pinned (`CreateContext`, the last argument of `add_vertex_with`/`add_edge_with`, the override point; `GraphTraversalSource::with_now`; a script stamps its evaluation `now()`, `script::pin_now`); the generated value is recorded as a plain value, so replay is deterministic. `check_defaults` (set/patch/validate) requires a valid default and `defaultFunction` only at the top level (`now` on a `date-time`, `today` on a `date`); saved-query parameter schemas reject `defaultFunction`. A `default` below the top level stays an annotation;
- `ValueType` (`types.rs`), the type of an `ElementProperty` value (`Null`, `Boolean`, `Int64`, `Float64`, `String`, `Uuid`, `Date`, `LocalDateTime`, `DateTime`, `Time`, `Duration`, `Vector(VectorElement)`, `Array`, `Object`, `Union`; display names `date`/`localdatetime`/`datetime`/`time`/`duration`/`vector<f32>`), used by `GType::Value`, casts and diagnostics; diagnostics name types with `PropertySchema::type_name`/`non_null_type_name` (`int64`, `union<int64|null>`), never JSON Schema's names;
- inference (`inference.rs`, `SchemaInferer`), which reports the exact logical type of each stored value per position (type arrays, `anyOf` for string+uuid, `required` only for keys every object at the position has), never guessing from string content; mode `none`, valid for its data in `open` and `closed`;
- validation and enforcement (`validation.rs`, `nested.rs`, `coerce.rs`). In `Open`/`Closed` a declared property coerces on write (canonical string → `uuid` or a temporal type, a `date-time` only with an explicit offset/zone; `int64` → `float64`); validation compares logical types exactly; reads never coerce. `required` and nullability (`null` in the type) are independent. `mode` is the default `additionalProperties` of nodes typed `object` (open = true, closed = false; an explicit value wins, `admits_additional_properties`); `Closed` also rejects undeclared labels and checks topology. Multi-label: each label checks what it declares and its `required`; an undeclared top-level key is allowed if ANY label admits additional properties; coercion follows the first label (label order) that declares the key; topology accepts an edge if ANY label of each endpoint matches (`*` matches all). Removing a required property is rejected (`check_removal`). `add_vertex_label`/`remove_vertex_label` validate the new label set first. A `Vertex`/`Edge` value can never be stored as a property (`GraphError::InvalidPropertyValue`). Each `GraphStorage` call validates atomically, every traversal is one unit (`tests/all/schema_gap_tests.rs` gap 4, `transaction_tests.rs`);
- applying a schema: `GraphStorage::get_schema`/`set_schema` (default `Unsupported`), `declared_property_schema`. In `Open`/`Closed` `set_schema` scans all data in one pass (`apply.rs` `scan_storage`) and fails with the aggregated `SchemaError::ExistingDataViolatesSchema` (groups with counts and sample ids, array indices collapsed into `[*]` with the first concrete path in `ViolationGroup::example_field`; every nested violation of a value, through the same `nested.rs` walker a write runs fail-fast via a `Sink`; graph and old schema unchanged); mode `None` applies without scanning. "Freeze the structure you have": `set_schema(infer_schema(), mode)` (Rust `GraphSchema::with_mode`; DSL/Python/session/wasm/dev server take the mode as an argument, `SchemaMode::parse` is the one error for an unknown name) always applies to the data it was inferred from, except `Closed` with unlabeled elements (`UNLABELED` groups, "N vertices without a label"; tested in `schema_freeze_tests.rs`, also on 40 generated graphs). A schema change is a database change: `Mutation::SetSchema`, commit seq, rollback, `UnitChanges.schema`;
- the seven methods on `GraphTraversalSource` (and Rhai both spellings, Python `Graph`, wasm): `get_schema`, `set_schema`, `patch_schema` (`patch.rs`, RFC 7396 on the canonical form), `validate_schema`/`validate_schema_patch` (`SchemaValidation`: violations report, diff, compatible), `infer_schema`, `diff_schema` (`diff.rs`: `SchemaDiff`/`SchemaChange`, compatible = backward compatible: data and clients written against the old schema keep working, i.e. the change only adds (an optional key, also to an open object) or relaxes (removing a property declaration from an open object, i.e. one admitting undeclared keys, counts as relaxing); tightening or removing a label or a closed object's key is incompatible; a `default`/`defaultFunction` change is `default_changed`, always compatible; static, conflicting data is `validate_schema`'s business). Authorization: Read Schema, `set`/`patch` Update Schema. The stream step is `infer_schema()` (Rust builder `infer_schema_step()`). In Rhai a schema is a plain map (rendered by the session visualizer via `script::schema_of_value`; Rhai maps sort keys);
- a meta-graph (`meta_graph.rs`, `to_graph`/`subgraph`), and visualization (`visualize.rs`: table/markdown/tree with nested property paths, mermaid with nested entities, plantuml, per-label JSON Schema, json).

User docs: `book/src/users_guide/schema_enforcement.md` (format reference, errors and why, modes, `default`, backfill recipe, diff rules, Pydantic).

**Definitions (catalog).** `graph/definition.rs` (book `users_guide/saved_queries.md`): the catalog of named definitions stored beside the schema. `Definition` = `DefinitionKind` (u8 newtype: `QUERY` = 1, `PROPERTY_INDEX` = 2, `COMPRESSION` = 3, 4-127 unassigned, 128-255 HOST kinds never assigned by the library: `DefinitionKind::host(n)`/`is_host`, stored `Opaque`, never damage, format spec 16 rule 8) + `DefinitionFlags` (bit 0 critical, others preserved) + name (unique per kind, case-sensitive) + `DefinitionBody` (`Query(QueryDefinition)` or `Opaque(Vec<u8>)`: payload bytes of a kind this version cannot decode, kept byte for byte). `QueryDefinition` (folder, description, dialect `graphersal-rhai/1`, source = one Rhai function, ordered params `QueryParam { schema: PropertySchema, default }`, meta, `extra` = unknown payload keys kept); saved queries are read-only, there is no `writes` field. `Definition::validate` (run by every `set_definition`) checks names (identifier, not a Rhai keyword), folders, sizes (`MAX_*` consts), parameter names (not `RESERVED_PARAM_NAMES`, which lives here, re-exported by `script/eval.rs`), schemas and defaults (`QueryParam::check_value`: coercion + nested validation); it never compiles the source (no Rhai in the core). Forms: `to_payload`/`from_payload` (the property map of the persisted payload, `params` as canonical JSON text), `to_json`/`from_json` and `catalog_to_json`/`catalog_from_json` (exchange form; lenient: unknown keys kept), the public payload codec `definition::encode_payload`/`decode_payload` (feature `persist`, wraps `persist/definitions.rs`, for host kinds), serde via the tagged form; `QueryParam::from_value` is the strict user-facing reader. `GraphStorage::definitions`/`definition`/`set_definition`/`remove_definition` (defaults: none, `Unsupported`); `TraversalGraph.definitions` (`Catalog`, max `MAX_DEFINITIONS`), `UndoEntry::Definition`, `Mutation::SetDefinition { kind, name, before, after }` (capture, `compact`, replay, `replay_lenient`, `apply_change_set`). Authorization: `Resource::Definition`/`ResourceKind::Definition` (Read list/get, Create/Update/Delete manage, Execute call). Rust API on `GraphTraversalSource`: `list_definitions`, `get_definition`, `set_definition`, `define_query`, `remove_definition`, `move_query`, `describe_query`; the DSL is **Saved queries (DSL)** below (Rhai `r.changes` has `definitions`). Persisted (`persist/definitions.rs`, format spec 6.3, 9.3, 16): one record `kind | flags | name | length | payload` for the manifest's definitions table (sorted by kind, name) and WAL op 10 `SetDefinition` (before/after `opt(definition)`); a known kind's payload is a property map whose keys are never `kind`/`name`/`flags` (`RESERVED_PAYLOAD_KEYS`, also checked by `validate`), an undecodable known payload is damage, an unknown kind stays `Opaque` and is written back byte for byte; a journal refuses (vetoes) storing a critical opaque definition. Tests: `tests/all/definition_tests.rs`, `definition_store_tests.rs` (every backend: WAL replay, checkpoint, fork, backups, ZIP, repair, rollback, read-only opens), conformance items `definitions_are_stored_validated_and_removed`, `rollback_restores_definitions`, `definition_changes_are_captured`.

**Compressed properties.** `value/compressed.rs` + `graph/compression.rs` (book `users_guide/compressed_properties.md`): a rule is a catalog definition of kind `compression` (`CompressionDefinition`: element, label, jpath of NAMES, codec lz4, `min_bytes`, `dictionary`; not critical); strings at rule paths are stored as the STORAGE-ONLY `ElementProperty::Compressed(Box<CompressedText>)` (self-contained: plain length, LZ4 block, `Arc` dictionary; verified by a round trip when made, so reads are infallible). It is never a stream, script, `ChangeSet`, export or file value: every read leaving the graph goes through `ElementProperty::logical`/`to_logical`/`with_text`/`text` (and the `From` conversions to `TraverserValue`, `into_node_property`, the physical codec, the persist codec, `Mutation::make_logical` in capture all decompress); equality, hashing and ordering are logical (`Compressed("x") == String("x")`). A new read site on stored values must use them; a new exhaustive match treats `Compressed` as a string (its out-of-line helpers keep recursive frames small: the 2 MiB test stack is tight). The invariant (`check_compression_invariant`, doc-hidden): a string at a rule path is compressed iff `>= min_bytes` and `<= 90 %`, nothing else is compressed; kept by the write path (`CompressionRules::prepare_*`, normalize after jpath writes and label changes), the explicit pass (`compression_after_change`: define/redefine/drop/undo, `recompress`, records nothing, emits only `SetDefinition`), rollback restores and the load pass (`compression_load_pass`: end of `read_snapshot`, salvage). `MemoryStats` has `compressed_values`/`compressed_plain_bytes`/`compressed_stored_bytes`/`compression_dictionary_bytes` (and `property_index_bytes`, see below). `lz4_flex` is a non-optional dependency. Tests: `tests/all/compressed_property_tests.rs` (differential battery, invariant after every write, randomized, the `#[ignore]` measurement), `definition_store_tests.rs` (every store path).

**Property indexes.** `graph/property_index.rs` (book `users_guide/property_indexes.md`, `optimizer/property_index.md`): a declared, ordered index `(element kind, label, key) -> value -> elements` is a catalog definition of kind `property_index` (`PropertyIndexDefinition`, facade `catalog`; one per (element, label, key); vertices and edges; a multi-label vertex is in every index of its labels); its ENTRIES are never persisted: every mutation path of `TraversalGraph` and its undo keeps them exact, a define/drop rebuilds that index, a load (`finish_load`) rebuilds all (also read-only and backup opens). Keys are logical scalars with `has()`'s exact equality (numbers ranged by float64, temporal values incl., a `datetime` by its instant, a compressed string by its text); arrays/objects are not indexed and never served. Trait: `GraphStorage::property_indexes`/`vertices_by_property_index`/`edges_by_property_index` (defaults: none; a result may hold more, never fewer, the caller re-checks). DSL `g.create_index(#{label, key, element?, name?, type?})`/`drop_index`/`indexes` (`createIndex`/`dropIndex`); `MemoryStats::property_index_bytes`. Every index has a `type` (`PropertyIndexType`, payload key `type`, always written, default `memory-ordered`); `PropertyIndexType::holds(&ValueType)` is the one index type x value type matrix (memory-ordered: the logical scalars, never array/object/vector). A type unknown to this version is kept byte for byte, never built or served, listed with `served: false` + `reason`; creating one is refused. The creation front ends (Rust `create_index`, DSL, session/HTTP/MCP; Python via the DSL) run `PropertyIndexDefinition::check_create` against the stored schema (a top-level key declared only as vector/array/object -> `DefinitionError::IndexTypeMismatch`, session field `key`); `set_definition`/replay/`apply_change_set`/loads never do; conflicts are per (element, label, key, type, transform). An index may carry a TRANSFORM (`PropertyIndexTransform`, payload key `transform`, absent = none; facades `catalog` and `storage`): `to_lower` keys the lowered text of STRING values only (compressed by their text), through the ONE lowering function of the step, `step_to_lower::lower_text`; `PropertyIndexDefinition::holds` = type `holds` x `PropertyIndexTransform::accepts` (to_lower: strings only), `check_create` refuses a key declared only as non-strings (`IndexTypeMismatch` with `transform`); an unknown transform is kept byte for byte, never built/served, refused when created (field `transform`); the default name appends `_to_lower` (after `_edge`). It serves TinkerPop's `has(key, traversal)` (`filter_steps/step_has_traversal.rs`, Rust `has_traversal`: ONE child = `values(key)` + the given steps, so ids/paths/auth are those of `filter(values(key)..)`; it renders as written) in the exact shape `has(key, __.to_lower().is(P))` (`index_condition` via `GraphStepMap::index_transform` + `GraphStepFilter::value_index_ranges`), `P`'s constants as given, only while the index's `PropertyIndexStats::skipped` (non-null values it does not hold) is 0, since `to_lower()` errors on them; lookups `GraphStorage::vertices_by_transformed_property_index`/`edges_..` (default none). Tests: `tests/all/property_index_tests.rs` (differential indexed vs. unindexed, `mod transforms`), `has_traversal_tests.rs`.

**Pipeline.** Traversals are built through `GraphTraversalSource` (`traversal/source.rs`) as a `Vec<GraphStep>`. `GraphStep` (`traversal/step/mod.rs`) is an enum of boxed trait objects, one variant per category:

| Category | What it does / examples |
|---|---|
| `Init` | `v()`, `e()` |
| `Append` | Direct extension steps |
| `Map` | 1→1: `values`, `id`, `label` |
| `FlatMap` | 1→N: `out`, `in`, `both`, `out_e`, `union`, `json_path` |
| `Filter` | `has`, `has_label`, `has_id`, `where_step`, `filter(traversal)` |
| `Barrier` | Full-stream aggregation: `count`, `sum`, `max`, `min` |
| `FlatBarrier` | Needs the full stream before emitting: `dedup`, `limit`, `repeat` |
| `SideEffect` | Non-transforming side operations, e.g. `profile` |
| `SideEffectMut` | Graph mutation: `add_v`, `add_e`, `property`, `drop`, `remove_property(keys...)` (explicit removal; `property(k, null)` still stores null), the label steps `add_label`/`drop_label` (vertices) and `set_label` (edges; Graphersal extensions, `Update` on `Data(vertex|edge)`) |
| `Modulator` | Modifies a step: `by`, `as_` |
| `As` | Step label |
| `Count` | Fused count |

- **Where step code lives:** each category has a `<category>_steps.rs` plus a directory with one `step_<name>.rs` per step. A new step goes into its category's directory.
- **Loops:** `repeat()` (`flatbarrier_steps/step_repeat.rs`) is a `FlatBarrier` that runs its body child traversal once per iteration on the whole frontier (BFS), or per traverser with an explicit stack for `g.with("repeat.order", "dfs")`. `times()`/`until()`/`emit()` are not `Modulator`s: their builders attach to the preceding `repeat()` through the `GraphStepFlatBarrier::as_repeat_mut()` hook (postfix), or push a body-less placeholder that a following `repeat()` fills in (prefix). Loop counters live in `TraverserContext::loop_stack` (one `LoopFrame` per active loop, never on the traverser); `loops()`/`loops(name)` read it. A loop without `times()` fails after `repeat.max_loops` iterations (`ExecutionOptions`).
- **Optimizer:** before execution, the pipeline runs through the rule-based optimizer (`traversal/optimizer/`). `TraversalOptimizer::default_pipeline()` rewrites the `Vec<GraphStep>` in place, nested child traversals first (bottom-up). The rules run in this order:
  1. `WhereUnnest`
  2. `AddPropertyFold` (`add_property_fold`): `add_v`/`add_e` plus the whole run of directly following constant `property(k, v)` steps (modulators `as_()`/`from()`/`to()` do not break it; last value of a repeated key wins) become ONE `add_vertex_with`/`add_edge_with` call (schema defaults applied there), so required schema properties are satisfied and a failing property leaves no element. The run stops at the first traversal-valued, `Cardinality`, jpath-keyed or other step. Folded properties live in `StepAddV`/`StepAddE.properties` (`AddElementStep::fold_property`, `GraphStepSideEffectMut::constant_property`); `.profile()` renders `add_v("L", properties: [...])`.
  3. `FilterReorder`: cheap `has_id`/`has_label` filters first.
  4. `HasIdPushdown`
  5. `SourceFilterPushdown`: folds `has_id`/`has_label` into `StepV`/`StepE` (never the zero-argument `has_label()`, "has any label", whose `labels()` is `None`; `not(__.has_label())` selects unlabeled elements).
  6. `PropertyIndex` (`property_index`): a `v()`/`e()` with folded labels (each with an index on the key) reads a property index for its folded `has(key, value)` and the `has(key, P)` (eq, within, ranges) in the run of pure filters after it; the `has` steps stay in the plan and re-check; skipped when the graph declares no index.
  7. `BarrierPushdown`: e.g. `out_e().has_label(x)` becomes `StepOutE(labels)`.
  8. `GroupCountPushdown`
  9. `CountPushdown`: a `count()` directly after the leading `v()`/`e()` (not necessarily the last step: `v().count().is(6)` fuses too) is computed from storage or an index (`count_only`).
  10. `LazyBarrier`: inserts a merge point (`lazy_barrier()`) between adjacent adjacency steps, only after vertex-yielding steps; an adaptive probe (4096 items, gives up below 1/16 merged) skips streams where nothing merges.

  After the rules, the path requirement analysis (`optimizer/path_analysis.rs`) runs on the final plan. It walks each level backwards and gives every physical step a `PathMode` (`None` / `Labels{set}` / `Full`): what the step must record into traverser paths so that later steps can read them. Nested traversals report their needs through the step that holds them. Paths live in a per-execution arena (`value/path_arena.rs`), and `Traverser.path` is a 4-byte `PathRef`. `g.with("path.analysis", false)` forces `Full` everywhere, for diagnosis.

  New rules go in `optimizer/rules/` and must be registered in `TraversalOptimizer::registry()` (`optimizer/mod.rs`), which pairs its stable `name()` string with a constructor and a default-on/off flag; give a new rule `default_on: true` unless it's genuinely experimental/opt-in (e.g. cardinality-dependent), matching this crate's convention that a rule ships on unless there's a specific reason not to. `Init` and `FlatMap` steps should expose filter parameters (label sets, ID filters) so rules can fold into them. Which rules ran for a given query is queryable two ways: `.profile()`'s output ends with an "Optimizer rules applied: ..." line naming every rule that actually modified the plan (top-level and nested, omitted when none fired), and `g.with("optimizer.disabled", ["rule_name", ...])` / `g.with("optimizer.enabled", ["rule_name", ...])` toggle specific rules by that same name for one execution (unknown or contradictory names fail with `TraverserError::InvalidOption` when the traversal executes, not at `with()` time). The current 10 rule names (`KNOWN_RULES`) and their default state are listed in `book/src/optimizer/index.md`.
- **Bulk:** `Traverser` carries `bulk: u64` (multiplicity, `Traverser::bulk()`); equal traversers are merged at merge points (`barrier()`/`barrier(n)`, the `repeat()` BFS frontier, optimizer-inserted `lazy_barrier()`), so path-count explosions stay cheap. Bulk is invisible: results are the same multiset with and without merging (only the order of duplicates may change). Merging is skipped for `Full` paths, containers, DFS repeat and mutating plans. `barrier(n)` validates `n` but does not chunk. Options: `bulk.merge` (default `true`; `false` is the differential-test oracle) and `bulk.max_expansion` (default 10 000 000 values; `BulkExpansionLimit`), the second line behind the byte budget `traversal.max_materialized_bytes` (see Resource limits). Code lives in `traversal/bulk.rs` (`merge_traversers`, `total_bulk`, `expand`); `withBulk(false)` is the option `bulk.one` (a merge keeps bulk 1, so duplicates collapse at `barrier()`). Docs: `book/src/users_guide/bulk_and_barriers.md`.
- **Sack:** `Traverser.sack: SackRef` (4 bytes in the former padding, `NONE` = null) indexes the per-execution `SackArena` in `TraverserContext.sacks` (`value/sack.rs`); scalars are interned, containers get fresh handles, and `size_of::<Traverser>() == 80` stays (guard test `traverser_stays_80_bytes`, a unit test in `traversal/traverser.rs`). `Operator` drives `sack(op)`, the merge operator of `withSack(init, op)`, `fold(seed, op)` and reducer side effects (`SideEffectValue::Reduced`, folded per step execution through `GraphStepSideEffect::finish_batch`); `Barrier.normSack` is the `Barrier` token. Merge rules: a sack without a merge operator merges only equal handles; with a merge operator (or `bulk.one`) the sack is ignored in the merge key and combined in encounter order, and `context.auto_merge` is false, so only an explicit `barrier()` merges (the `repeat()` frontier and `lazy_barrier()` pass through). The merge pass is monomorphised (`merge_inner::<S, OPERATOR, ONE>` in `traversal/bulk.rs`). **Child-input rule (TinkerPop):** a child traversal that receives a real traverser keeps the parent's sack (`split`/`with_parts(.., source.sack)`); an object-valued `by()` projection (`path().by`, `select().by`, `tree().by`, `where(P).by`, `math` variable `by`) gets a fresh traverser with the *initial* sack (`Traverser::start(context, v)`). Docs: `book/src/users_guide/sack_and_operators.md`.
- **Pop:** `select(Pop, labels...)` reads a repeated path label through `PathArena::labelled` (`value/path_arena.rs`): `first` oldest, `last` newest, `all` always a list, `mixed` value-or-list. A map key or side effect of that name wins over the path and ignores the pop. Semantics are vanilla Gremlin (gremlin-core 3.7.2 `ImmutablePath`): a list-valued occurrence is **not** unwrapped; the one replicated quirk is that `mixed` follows `Path.get(label)` (appends to a list-valued oldest occurrence, done on a copy). `select(Pop, traversal)` / `select(traversal)` is `StepSelectTraversal` (`map_steps/step_select_traversal.rs`): the key is the first result of a child run on the incoming traverser with its path; a string key is looked up like `select("key")` (map key, side effect, path label read with the pop), a non-string key (an element) only as a key of the incoming map (`group()` keys); no result or a key not found filters; only the last `by()` applies. **Path recording:** every pop except `last` (and every traversal key) makes `path_requirement()` return `Full`, because `Labels` mode drops earlier occurrences; plans without a Pop are unaffected. The plan-time undeclared-label check (`required_labels()`) covers the Pop forms but is switched off by any step in `MAP_PRODUCING_KINDS` (`path_analysis.rs`: `unfold`, `values`, `constant`, ...) anywhere in the query, by design. Tests: `tests/all/pop_tests.rs`; `tests/all/pop_notation_tests.rs` is the dual-notation matrix (every spelling x pop x receiver spelling against the Rust API; extend it when a Pop form is added). Docs and the Groovy-to-Rhai copy-paste cheat sheet: `book/src/users_guide/select_pop.md`.
- **Profiling:** `.profile()` returns `TraversalMetrics` (`traversal/metrics.rs`: pure data with getters, snake_case, `Display` = the text table; map/JSON via `to_property()`/`to_json()` through the physical codec), recorded by the crate-internal `ProfileContext` (`step/profile.rs`) only inside the `is_profile` gates. It must show the *optimized* plan: fused steps under their real names (e.g. `v(labels: ["person"]).count()`), with accurate timings and traverser counts. **Extensibility rule:** a new `ProfileType` only adds a new optional section to `Metrics` (like `memory`); existing fields never change (`tests/all/execute_tests.rs` checks it). **Step ids** (`Metrics::id`, `"3.1.0"` = step 3, child traversal 1, step 0) are static plan positions; the child numbering is defined once by `GraphStep::child_traversals_mut` (own traversal arguments first, then modulator children in attachment order; it also drives `optimize_nested`), stored in `AnonymousTraversal::child_index` by `GraphStep::number_children` in `execute_steps`, and passed down as `LevelAt`/`StepAt`. A new child-holding step overrides `child_traversals_mut` (not `optimize_nested`) and gets an id case in `execute_tests.rs`. Errors carry the same ids (their frames leave out the display-only `limit(n) [display]`, `plan_frame`): `TraverserError::StepFailed.child_index` + `step_index`, read by `TraverserError::step_location()` (`StepLocation { step_id, step_path }`). Errors found before the run are located too (`source.rs` `locate_pre_run_error`): a plan-time error of the validation pass (rejected modulator, `plan_check()`, `ValueError::UndeclaredLabel`) and a denied step become the `StepFailed` chain of their step; only errors without a step (invalid/locked options) stay bare.
- **Rendering and spelling:** every step renders ONE canonical snake_case text (`GraphStep::get_name`, reads like the DSL call: `has_label("person")`, `where(__.out())`); values inside it are Rhai literals from `value/literal.rs` (never `Debug`, rule 14), cut after 64 characters / 16 items (`"aaa…" (8192 chars)`). `g.with("render.spelling", "camel")` (`Spelling::Snake`/`Camel`, `traversal/spelling.rs`; front ends: `--spelling`, `/set spelling`) respells the diagnostics ONCE, at the boundary in `GraphTraversalSource::run()`: the profile and the error (`TraverserError::respell`), also an error before the run (authorization check, option parsing; `context::requested_spelling`); an error without a step frame is wrapped in `TraverserError::Spelled` under camel. `respell` renames every identifier followed by `(` outside string literals through the registered name pairs, so `help()` prose is written in the canonical snake_case DSL style (`as("a")`, `where(..)`, `out()`, `GType.LONG`, `__.out()`; no Rust API names such as `as_`, `where_t`, `out(None)`, `GType::LONG`) and comes out in either spelling.
- **execute():** `execute()`/`execute_with(ExecOptions)` (`traversal/execution.rs`) return an `Execution` (`results`, `error`, `profile`, `mutated()`, `changes()` = `UnitChanges { data, schema }`; `into_result()`), never `Err`: every error, also one before the run starts (a `PermissionDenied`), is inside it, with the partial profile up to the failing step; a failed run is rolled back and its `results` are empty. Engine: `GraphTraversalSource::execute_items` (also behind `profile_with` and the DSL). Rhai: `profile()` returns a `TraversalMetrics` value (a failure is a script error), `execute()` / `execute(#{profile, profile_types})` return a `ScriptExecution` that never throws (`script/execution.rs`); the session visualizer (`try_render_value`) renders metrics as the table and an execution as results then table. Docs: `book/src/users_guide/profiling_and_execute.md`.

Formats: persist value tag 14 (file format version 2), `ChangeSet` tag `graphersal:Vector`, the physical codec/GraphSON export as a plain list (`g:List` of `g:Float`; the import reads the exact tag), GraphML only through a declared schema. A vector is never a property index key;

DSL: step `embed()`/`embed(key)`/`embed([key,] #{embedder})`, global `embed(text[, #{embedder}])`, `g.embedders()` (asks nothing). Permission: `Execute` on `Resource::Embedder { name }` (`ResourceKind::Embedder`), every embedder incl. the built-in; `read_only()` allows it. No embedder runs in replay/recovery/loads (values stored plain). **Job `embed_property`** (`vector/embed/job.rs`, facade `EmbedJob`/`EmbedReport`/`EmbedJobError`): `Graph::embed_property(job, embedders, cancel, progress)` (+ `AnyGraph::embed_property`) collects ids (read lock), then per page reads texts (read lock), calls the embedder WITHOUT any graph lock, writes in one `transaction` per page re-reading each text (`skipped_changed`/`skipped_removed`); `NoFeatures { index }` = skip that text and call again; a failure keeps earlier pages (partial report), `only_missing` (default) makes a rerun continue; inside an open unit (`unit_started_at().is_some()`: a whole-script unit's private graph) or through `EmbedJob::run_in(&mut S, ..)` (inside a transaction) every phase runs under one lock, pages = savepoints. DSL `g.embed_property(#{label, from, to, element?, embedder?, only_missing?, batch?})` (both spellings, report map) asks Read+Update `Data(element "label")`, Execute `Embedder`, and Update `Schema` only when it declares the property (`EmbedJob.schema_update` check); a saved query is denied. **Provenance** (`vector/embed/provenance.rs`): the job needs an ATTACHED schema (mode open/closed, `EmbedError::SchemaNotAttached`), never attaches one; `plan` declares an undeclared `to` (vector of the embedder's element/dimension/metric + `embedder: model`) or adds `embedder` in the unit of the FIRST page (a `SetSchema`), refuses another model (`EmbedderMismatch`) and a declaration that is not a vector or has another dimension (`SchemaError::TypeMismatch`); another element kind is allowed (the write quantizes, `Vector::quantize`, like any schema write), and a text query on a `bit` property quantizes its query to bits. **Text queries**: `nearest(key, "text", k)` / `similarity(key, "text")` (`VectorQuery::Text(TextQuery)`, `From<&str>`): `run()`'s `bind_embedders` binds the candidate embedders of every model the attached schema declares for the key (`text_query_candidates`, `Embedders::by_model`; refusals `SchemaNotAttached`, `NoDeclaredEmbedder`, `TextQueryKey` (jpath/value form), `ModelNotRegistered` when none is registered), the permission check asks Execute on each candidate (`text_query()` arms in `for_each_access`), at run time each element's declared model picks the candidate (all met must agree: `ModelConflict`), the text is embedded ONCE per execution (cache in the step, reset on clone), and the profile renders `nearest("emb", "text", 2, embedder: "hash-ngram/1")`.
- `element_value.rs` (`VertexValue`/`EdgeValue`/`VertexRef`: what a terminal returns for an element, id/label(s)/endpoints apart from the properties; JSON is untyped GraphSON 3, book `users_guide/vertex_and_edge_values.md`) and `record_key.rs` (`RecordKey`: `Name`/`Id`/`Label`/`Out`/`In`, so `elementMap()`/`valueMap(true)` keep `T.id`/`T.label`/`Direction.OUT|IN` apart from properties named `id`/`label`, book `users_guide/id_and_label_keys.md`);
- `physical.rs` — the physical (JSON-types) codec: `lower` logical → physical, `lift` physical → logical by declared `ValueType`; the only place where values cross the I/O boundary.

Serde for `ElementProperty` is plain JSON via the codec (a `Uuid` serializes as its canonical string); only `ChangeSet` serde adds type tags (see **Change capture**).

**Script DSL.** `script/` wraps the Rust API in `ScriptGraphTraversalSource` and registers each step with Rhai. It is split into modules (the layout comment at the top of `script/mod.rs` lists them; no file is above ~1k lines): `eval.rs` (`graph_scope*`, `eval_*`, parameters, `RESERVED_PARAM_NAMES`), `engine.rs` (`engine_with_limits`: limits, authorizer, keyword-token rewriting), `access.rs` (the session authorizer, private graphs, the `import` resolver), `register/` (the Rhai registrations by category: `types.rs`, `tokens.rs`, `terminals.rs`, `steps.rs`, plus the `register_variadic!` macros; they go through `registry.rs`'s `Registry`, which mirrors the `Engine` registration API into `rhai::Module`s built once per thread, and `new_engine()` attaches those and a shared Rhai standard library to every engine by pointer, so `engine()` costs microseconds), `tokens/` (one file per token class), `step.rs` (the `Step` AST), `source/` (`ScriptGraphTraversalSource` and its builder methods by step family), `convert.rs` (`Step` -> engine steps), `terminals.rs`, `mutating.rs` (`is_mutating()`), `plan.rs` (the script group of `AnyGraph`), `dynamic.rs` (`Dynamic` conversions), `render.rs`, `tests.rs`. **Any storage:** a source holds its graph as `Arc<dyn AnyGraph>` (`ScriptGraphTraversalSource.g`; `None` runs on a scratch `TraversalGraph`), and `graph_scope*`, every `eval_*` and `ScriptGraphSource::graph` take `impl IntoAnyGraph`; a terminal is ONE `AnyGraph::run_plan(&ScriptPlan, Terminal)` call (the blanket impl lowers for `&S` under `read()` or `&mut S` under `write()`), schema/catalog/statistics/memory/`mark`/io/`export_snapshot` go through the other `AnyGraph` methods, and `eval_value_atomic`/`eval_value_dry_run` run the script through `AnyGraph::run_unit` (write lock, `std::mem::take` into a private `Graph<S>`, swapped back on return and unwind; a returned traversal is retargeted by comparing `Arc` data pointers, `plan::same_graph`). Graphs a script builds (`GraphSource::*`, `__`, `_g`, `subgraph`/`cap`/`toGraph`, `schema.toGraph()`, `TraverserValue::Graph`) stay `Graph<TraversalGraph>`; a `withSideEffect(name, g)` target is downcast to one (`AnyGraph::into_any_arc`), a foreign one fails with `GraphError::Unsupported` (`error::SUBGRAPH_TARGET`). **Lowering lives in one place:** `convert.rs`'s `lower()` turns the `Step` AST into engine steps with the `AnonymousTraversal` builders for `g` (`ast_convert_to_gts`) and `__` (`ast_convert_to_anonymous`) alike, so a new step gets exactly one arm there. The root differs only in three hooks: it applies the source steps (`Step::Source(SourceStep)`: `withSack`, `withSideEffect`; inside `__` they become a marker step that fails with `TraverserError::SourceStepInChild` in the plan-time validation pass), a leading `mergeV()`/`mergeE()` starts it (`merge_*_lowered(.., start)`), and a no-step `by()`/`from()`/`to()` names `g` (`GraphTraversalSource::adopt_lowered`). A builder whose `GraphTraversalSource` version behaves differently at the root needs such a hook too; `tests/all/source_step_tests.rs` guards that `g.X` and `__.X` lower to the same plan. Public items are re-exported from `script/mod.rs` under their `graphersal::script::X` paths. Never compare a script type by a type-name literal (`"graphersal::script::X"`): `std::any::type_name` includes the defining module, so use `Dynamic::is::<T>()` or `std::any::type_name::<T>()`. Every step is usually registered in both spellings, snake_case (`has_label`) and Gremlin camelCase (`hasLabel`), from ONE entry (`registry.register_fn_as(&["has_label", "hasLabel"], f)`, `register_variadic!(registry, ["has_label", "hasLabel"], ..)`), with one overload per arity (`out_empty`/`out_single`/`out`). `script/surface_tests.rs` snapshots the whole registered surface into `crates/graphersal/tests/snapshots/script_surface.txt` (a DSL change shows up there; regenerate with `GRAPHERSAL_UPDATE_SURFACE=1` and review the diff) and checks that both spellings of a name have the same overloads (names with one spelling on purpose are listed in `SINGLE_SPELLING` with their reason). **Function docs:** `register/docs.rs` holds one entry per DSL function (receiver + spelling-independent key: one sentence in the canonical snake_case style, a runnable example on the modern graph and its result); `Registry::register_fn` attaches it as `docComments` to every overload and spelling (module functions via `Registry::doc_comments`, the few `#[export_module]` plugin functions carry the same text as `///`). The playground completion tooltips (`graphersal-session` `completions`) and the MCP `graphersal://dsl-reference` read it from the metadata; `register/docs_tests.rs` fails when a catalogue function has no text or a stale one, when an entry is unused, and when an example does not give its documented result. Data terminals (`toList()`, `next()`) return native Rhai values. A traversal with no terminal is rendered by the session visualizer. `Column.keys`/`Column.values` (also `Column::keys` and the bare scope constants `keys`/`values`) feed `select(Column)`. UUID literals use Java notation: `UUID.fromString(..)` / `UUID.from_string(..)` (and `UUID::…`); Rhai carries `Uuid` values natively (`ScriptUuid`), never as strings. A diagnostic never names a Rust type: a wrong argument is described with `type_name_of`/`dynamic_text` (`dynamic.rs`, display names from `register::display_type_name`: `int64`, `float64`, `Predicate`, `GraphTraversalSource`), and Rhai's own type and call errors go through `script::map_eval_error` (every `eval_*`, the CLI, the playground and the fuzzer use it).

Token pattern (`Column`, `Scope`, `Cardinality`, `Direction`, `Merge`, `Operator`, `Barrier`, `Pop`, `SchemaMode`, `DT`): a Rust enum registered as a Rhai type, a `register_static_module("X", ..)` for the `X::y` spelling, and a marker type (`ScriptX`, pushed into the scope in `graph_scope()`) with getters for the `X.y` spelling. Provide both spellings and add the global name to `RESERVED_PARAM_NAMES` so a parameter cannot shadow it. The unit test `reserved_param_names_match_graph_scope` (`script/tests.rs`) builds `graph_scope()` and fails if a pushed global is missing from the list (or a listed one is not pushed), so a new token class cannot be forgotten; it also covers `T`, `By`, `Order`, `Pick`, `GType`, `CastPolicy`, `ProfileType`. `Column`, `Pop` and `DT` are the only classes that also have bare constants (`keys`/`values`, `first`/`last`/`all`/`mixed`, `second`/`minute`/`hour`/`day`, plain `push` in `graph_scope()`, never `push_constant`: Rhai folds `${const}` with the Rust type name); `keys`/`values` are reserved, of `Pop` and `DT` only the class name, so `let first = ..` or `let day = ..` shadows the bare constant (the test's list of shadowable constants is in `script/tests.rs`). Every token value (and every marker, a `Set.of(..)`, a predicate, an anonymous traversal) prints as its DSL literal through ONE trait, `value::literal::TokenLiteral` (`Scope.local`, `P.gt(1)`, `__.out()`): its `to_string`/`to_debug` registrations and the session visualizer (`script::render::token_literal`, which recognizes every token type; a new token type is added there and gets a `TokenLiteral` impl) use it; `every_graph_scope_token_renders_as_its_dsl_literal` (`script/tests.rs`) walks every class of `graph_scope()` through the function signatures and checks the text round-trips. Predicates and `by()` arguments are `P.x(..)`/`TextP.x(..)` (plus the lowercase bare globals `gt(30)`, `within(1, 2)`), `By.X(..)` and `jpath(..)`; PascalCase twins (`P::Eq`, `TextP::StartingWith`, `By::Property`) exist only in the static modules (`ArgPPascalModule`/`TextPPascalModule` in `tokens/predicate.rs`), never as bare globals. Every DSL name has both spellings except those in `SINGLE_SPELLING`. `select` dispatches on a leading `Pop` (labels or one key traversal). Map keys that mirror tokens are reserved *strings*, not token values: `"T.id"`, `"T.label"`, `"Direction.OUT"`, `"Direction.IN"` (and `Merge.outV`/`Merge.inV` become `"Merge.outV"`/`"Merge.inV"`) in `mergeV()`/`mergeE()` maps; see `book/src/users_guide/upserts.md`.

**Saved queries (DSL).** `script/saved_query.rs` (book `users_guide/saved_queries.md`): source methods, not steps, both spellings (`query`/`queries` one word): `g.define_query(#{name, body, folder?, description?, params?, meta?})` (body = ONE Rhai function named like the query, no other statements; params = name -> type name or `#{schema, default}`, as a set equal to the signature, stored in signature order; description defaults to the doc comment), `g.define_queries(folder, source[, params_by_fn])` (each function its own query, text cut from the source by the body's span, doc comments as descriptions, all in one `TraversalGraph::transaction`), `g.query(name[, #{args}])`, `g.queries([folder])`, `g.get_query`, `g.drop_query`, `g.move_query`, `g.describe_query`. A call: start position only (`g.v().query(..)` / `__.query(..)`, the source's `anonymous` flag, fail with `ScriptError::QueryNotAtStart`), `Execute` on the query first, depth bound `MAX_QUERY_DEPTH` 16 (`ScriptAccess.query_depth`, `QueryDepthExceeded`), arguments checked by `QueryParam::check_value` (`Unknown`/`Missing`/`InvalidQueryArgument`, values only), the body compiled through a per-thread cache keyed by name + dialect + params + source text (so redefinition and rollback never meet a stale entry; `InvalidQueryBody`), then `call_fn` on the caller's engine in `eval::scope_with_access` with `g` = the caller's graph under `ScriptAccess { read_only: true }` whose authorizer is the `ReadOnly` wrapper (Create/Update/Delete on Data, Schema, Definition, File denied with the reason `error::SAVED_QUERY_READ_ONLY`, whose `PermissionDenied` help explains the rule). The access travels with every source built in the body, so a returned traversal stays read-only (`is_mutating()` is false for it; `plan_writes()` is the raw mapping); a returned traversal whose plan writes is refused (`QueryReturnedWrite`). Errors from the body get a line `in saved query: "name"` before their `Help:` (limit/termination errors pass through unchanged). `default` is rewritten from a Rhai reserved word into an identifier (`engine.rs`), so `#{schema: .., default: 20}` parses. Tests: `tests/all/saved_query_tests.rs`, `permission_tests.rs` (`saved_queries`), `error_diagnostics_tests.rs` (`saved_query_errors_carry_their_help`). Front ends: `script::check_saved_query` (the call's compile check, public for hosts) backs `graphersal-session/src/queries.rs`; the playground's Catalog manager, editor and run form (`playground/js/saved-queries.js` model, `components/catalog.js`, `components/saved-queries.js`; the run form writes `g.query(..)` into a tab), MCP tools, Python `Graph.queries/get_query/define_query/drop_query/call_query`; `StoreInfo::definitions` (`graphersal store info`, the Store menu).

**Resource limits.** `script/limits.rs`: `ScriptLimits` (`#[non_exhaustive]`, builder `with_*`, `Default` = SAFE, `unlimited()` for trusted local front ends) is installed by `engine_with_limits`; `engine()` and the `eval_*` functions use the SAFE defaults, `eval_value_with_limits` takes explicit ones, and Rhai's limit errors map to `TraverserError::ResourceLimitExceeded` (`resource_limit_from_rhai`). The traversal side is a set of administrative options (`Update` on `Resource::Option`), lockable through `ExecutionPolicy` (`context.rs`): `traversal.max_traversers` (checked once per step boundary in `execute_steps`), `traversal.max_materialized_bytes` (1 GiB native, 256 MiB wasm32: a per-copy size estimate in every bulk expansion, bucket push and `repeat()` iteration), `traversal.max_string_bytes` (16 MiB: strings built by steps such as `replace`, `concat`, `format`, `as_string`) and `traversal.max_value_depth` (128, also `ScriptLimits::max_value_depth`: script ingress, parameters, the depth a property write leaves behind, each `repeat()` iteration); the evaluation deadline is checked inside materializing loops too. **Cancellation** (`traversal/cancel.rs`): `CancelToken::scope(|| ..)` makes every execution started on that thread check the token wherever the deadline is checked (`Deadline` carries it), failing with `TraverserError::Cancelled` (the unit rolls back); a host stops pure Rhai loops itself with `on_progress` (`graphersal-session` does both; the dev server cancels through it). **Memory budget** (`traversal/memory_budget.rs`, off by default): `memory.limit` (bytes, or `"auto"` = cgroup v2 `memory.max`/v1 `memory.limit_in_bytes` minus `memory.headroom`, read once per process, never on wasm32; `cgroup_limit_at(root)` is the injectable reader) is parsed into `ExecutionOptions::memory`, started once per `run()` (`MemoryBudget::start`: tracked = process live heap via the `TrackingAllocator` global counter, else `GraphStorage::memory_footprint_bytes` plus element counts; `TraversalGraph` caches that walk in `graph/memory.rs` `FootprintCache` keyed by commit seq + element counts, not while an open unit holds uncommitted changes) and checked at every step boundary (`check_memory_budget`) and at the `max_materialized_bytes` checkpoints (`ExpansionLimits::memory`, `check_loop_traverser`); never a walk per check. Units that are not traversals use the same budget from the graph's `ExecutionPolicy` default (script imports also the session presets): `UnitBudget` checks a live GraphML/GraphSON import and `apply_change_set` every `UNIT_CHECK_INTERVAL` (4096) elements and at the end, and `commit_undo_unit` checks every outermost unit (started in `begin_undo_unit`); only a unit that grew the measure fails, with `GraphError::ResourceLimitExceeded { operation }`, rolled back. Hosts set it as an `ExecutionPolicy` default or session preset (CLI `--memory-limit`/`--memory-headroom`, Python `Graph(memory_limit=..)`). `engine_with_options(limits, authorizer, options)` puts host presets (`evaluationTimeout`, ...) on every source of a session (`g`, `_g`, `__`, `GraphSource::*`). The native front ends evaluate scripts on a thread with a 64 MiB stack (CLI `main.rs`, Python `script_thread.rs`), because Rhai itself recurses on deeply nested values. Rhai measures arrays per call (quadratic `push` loops), so keep the array/map defaults modest. New limits go into the table in `book/src/users_guide/resource_limits.md` and get a `help()` arm in `error.rs` (`resource_limit_help`).

**Permissions.** `graph/authorization.rs`: an `Authorizer` (`authorize(&AccessRequest) -> Result<(), Denied>`, plus `resolve_file(path)`, default identity) decides each `AccessRequest` = `Action` (`Read`/`Create`/`Update`/`Delete`/`Execute`/`Custom(&str)`) x `Resource` (`Data { element: Option<ElementKind>, label: Option<&str> }`/`Schema`/`Definition { kind, name }`/`File { path }`/`Option { key }`/`Embedder { name }`/`Custom { kind, name }`; all `#[non_exhaustive]`; `Custom` is never produced by the library, a server checks its own resources with the same `authorize`). The subject lives inside the authorizer instance; roles are not a library concept. **Everything is allowed by default** (`AllowAll`), in the Rust API (`GraphTraversalSource.restrictions` is `None`) and the script entry. `AccessPolicy` is the ready-made policy (bit table of allowed `ActionKind` x `ResourceKind`, `allow_all()` = `Default`, `deny_all()`, `read_only()` = Read on Data+Schema+Definition and Execute on Definition, `allow`/`deny`/`allow_resource`/`deny_resource`, `with_file_root(dir)` implemented in its `resolve_file`). `with_authorizer(a)` attaches a check (options set before are host presets). The check (`traversal/permission_check.rs`, `Restrictions::check`) runs once per execution in `run()`, BEFORE the optimizer, on the plan as written, child traversals included: extra required requests, then administrative `g.with()` keys the query set itself (`context.rs` `ADMIN_OPTION_KEYS` -> `Update` on `Option{key}`; `repeat.order`, `bulk.one`, display and unknown keys ask nothing), then every step's requests (`GraphStep::for_each_access`: only steps that reach graph data, i.e. sources, adjacency steps and `subgraph`, ask for a read, value-only steps ask nothing), each distinct request asked once per execution; no per-element checks. A denial is `TraverserError::PermissionDenied { step, request: AccessRequestBuf, reason }`, located like a failing step. Script entry: `engine()`/`graph_scope(g)`/`eval`/`eval_value`/`eval_*_params` allow everything; `engine_with_limits(limits, Arc<dyn Authorizer>)`/`engine_with_options` (engine tag for `GraphSource::x()`/`schema.toGraph()`, `import` resolver: `Execute` on the module `File`, resolved by `resolve_file`; `script/access.rs`), `graph_scope_with_options(g, options, authorizer)`, `eval_value_with_limits`/`eval_value_atomic`/`eval_value_dry_run` take one. A graph the script built itself (`GraphSource::*`, `__`, `_g`, `subgraph()`/`cap()`/`toGraph()` results) is private (`ScriptGraphTraversalSource.private`): a request that writes data or schema (`AccessRequest::writes_graph`) is allowed without asking, unless the plan writes a subgraph into a host graph (`withSideEffect(name, g)` asks `Create` on `Data`). Source methods that are not steps ask themselves (`require`/`require_file`: `export_graphml` = Read Data + Create File, `import_graphml` = Create Data + Read File, `set_schema`/`patch_schema` = Update Schema, `get_schema`/`infer_schema`/`diff_schema`/`validate_schema*` = Read Schema (a schema is never read from a file), `GraphSource::file` = Read File, `statistics`/`memory_usage` = Read Data). The CLI and Python allow everything (Python: `policy=AccessPolicy..` per call), the playground `AccessPolicy::allow_all().deny_resource(File)`; integration tests import the script API from `tests/all/script_host.rs` (AllowAll for the entries that take one), except `permission_tests.rs`. A new step that touches files or the schema, or a new administrative option, needs its requests; docs: `book/src/users_guide/permissions.md`.

**Property keys (jpath).** A step that takes a property name takes `impl Into<PropKey>` (`value/prop_key.rs`: `PropKey::Name` | `PropKey::Path(JsonPath)`; `PropKeys` for the list-taking steps), and the Rhai binding takes a `Dynamic` that is a string or a `jpath("a.b[1]")` (`JsonPath`, parser in `value/json_path.rs`: RFC 9535 singular query, `[-1]`, bracket names). A plain string is always a literal name and is never sniffed or parsed. A name builds the old step unchanged; a path builds a separate step with the same name (`step_has_path.rs`, `step_values_path.rs`, `prop_path.rs`, `PathKeys`) that exposes no `keys()`/`labels()`/`ids()`, so no optimizer rule can fold it, and it reads by reference (`descend_property`), cloning only the leaf. A missing path is an absent property, never an error. `properties(jpath)` yields `TraverserValue::PathProperty` (materialized path text and leaf). Writes and removals go through the `GraphStorage` methods `set_*_property_path` / `remove_*_property_path` (default impls on a copy; `TraversalGraph` mutates in place only with `SchemaMode::None`), and nested schema validation and leaf coercion live in `graph/schema/nested.rs`; write faults are `GraphError::InvalidPropertyPath { fault: PathWriteFault }`, a removal never errors on a bad path. A new name-taking step must accept a `PropKey` in both spellings and say in its `///` why if it does not. Docs: `book/src/users_guide/jpath_keys.md`.

**Errors.** `error.rs` defines `TraverserError`, its sub-errors, and their `help()` texts. Tests for `help()` wording live in `tests/all/error_diagnostics_tests.rs` when a query can trigger the error. Named-field error variants are `#[non_exhaustive]`, so a test that builds an error value by hand lives in the `#[cfg(test)]` module of `error.rs`.

## Rules

1. **No panics in step or script paths.** Don't use `unwrap`/`expect`/`panic!`. Map every failure to a `TraverserError` variant. Arbitrary user queries must never crash the engine.
2. **Keep DSL parity.** Any change to a Rust step also updates its Rhai binding (builder method in `script/source/`, registration in `script/register/`), in both spellings, registered from one `register_fn_as` entry, with its doc entry in `script/register/docs.rs` (one sentence + an example checked by the test); update the surface snapshot (`GRAPHERSAL_UPDATE_SURFACE=1`).
3. **Mutating steps.** A mutating step is a `SideEffectMut` (or `drop()`); `GraphStep::for_each_access()` (`traversal/step/mod.rs`, the single step -> `AccessRequest` mapping) gives it its `Create`/`Update`/`Delete` request on `Data` (with the element kind and the label when the plan states them, `static_labels()`), and the authorization check, `GraphStep::mutates()` (the path analysis' `mutates`) and `ScriptGraphTraversalSource::is_mutating()` derive from it. A mutating step in another category, or a new reading step that knows its element kind, needs an arm there. Add Rhai-level mutation tests in `tests/all/script_tests.rs` and a denial case in `tests/all/permission_tests.rs`.
4. **Evaluate lazily; don't allocate per item.** Steps must not allocate `HashMap`/`IndexMap`/`String` keys or clone properties for each traverser. Materialize (`into_node_property`) only at terminal steps. Steps propagate `bulk` (`Traverser::split`/`with_parts`), counters add it, and materializing steps expand it through `bulk::expand`. `count`, `limit`, `has`, and `profile` stay lazy.
5. **Keep optimizer and profile in sync.** For every new source or expansion step, check whether it can take pushdown parameters. Keep `.profile()` accurate for fused steps.
6. **Update `help()` for new steps.** When a step is added or gains capabilities, go through every `help()` in `error.rs`. Name the step wherever it can now fix the error, with a runnable example built from the failing query. Keep the existing advice. Assert each changed message in `tests/all/error_diagnostics_tests.rs`, or in the test module of `error.rs` when the error has to be built by hand. Spelling follows TinkerPop: the coercion steps are `as_string()`, `as_bool()`, and `as_number(GType::LONG)`. `GType` is the type-token enum. `T` means only `T.id`/`T.label`, never a type.
7. **Don't infer types from content.** A string stays `string`, even when it looks like a date, UUID, or IP. Logical types come only from an explicit schema declaration or a per-value type tag (e.g. `{"@type": "g:UUID", ...}`). Never add a content-sniffing detector, because an ambiguous parse like `"03/02/2024"` corrupts data without raising an error.
8. **Keep the public API small.** The crate root holds only the modules and the domain types `TraversalGraph`, `GraphTraversalSource`, `GraphSource`, `TraverserValue`, `ElementProperty`, `TraverserError` (+ `CompactString`). NO public glob re-exports, and no third-party type in the API except `CompactString`. Query writers use `prelude` (graph, sources, `GraphStorage` for the graph's methods, values, tokens, `GraphSchema`/`SchemaMode`, `Execution`, errors); integrators use the facade modules (`src/<name>.rs`, `pub use` lists with module docs naming their audience, each public item in exactly one of them besides the prelude): `storage` (`GraphStorage` and EVERY type in its signatures; its doctest implements a storage with only `storage::*` + `prelude::*`), `changes`, `auth`, `catalog`, `schema`, `profile`, `exec`, `error`, `temporal`, plus `script`/`io`/`persist`/`alloc_tracking`; a new public type goes into the one that fits. `graph`, `traversal` and `value` are `pub(crate)`: crate code reaches their items through `pub(crate)` globs in `lib.rs` (`use crate::*;`), the public documentation of their topics lives in the facade module docs. Step internals, buffers, AST converters and helper types are `pub(crate)`; a helper type that a public signature needs (`ArgStrings`, `IntoSelectArgs`, `TraverserPath`, `TextRegex`) stays `pub` inside a private module, so it cannot be named outside the crate. A storage outside the crate builds the `#[non_exhaustive]` `GraphError` variants it returns through constructors (`GraphError::unsupported`, `element_removed`, `duplicate_vertex_id`, `invalid_property_value`, `invalid_property_path`, ...), and runs the contract's write checks through the public helpers in `storage` (`graph/write_checks.rs`: `check_property_value`/`check_properties`, `check_label`/`normalize_vertex_labels`, the jpath helpers `path_property_name`/`write_path(_in)`/`remove_path(_in)`; `TraversalGraph` and the trait defaults call the same functions; `JsonPathSegment` and `JsonPath::segments()` are public).
9. **Library code logs through `tracing` macros.** Never `println!`/`eprintln!`/`dbg!`.
10. **Dependencies.** Add a new crate only with justification. Declare it in the root `[workspace.dependencies]` and reference it with `x.workspace = true`.
11. **Tests and docs.** New public features get integration tests in `crates/graphersal/tests/`. Every public item has a `///` doc comment (`#![warn(missing_docs)]` in `graphersal`'s `lib.rs`, denied by `-D warnings`; `graphersal-session` denies it).
12. **English** in every on-disk artifact: code, comments, and docs. Chat may be in any language.
13. **Steps that read `Traverser.path` must override `path_requirement()`**, and steps that hold child traversals must override `analyze_nested_paths()`. Otherwise the path analysis does not record what they read. Verify the result with `.profile()`, which shows `[path: ...]` on each step that records something.
14. **`Debug` is never a data converter.** `{:?}` is only for `Debug` impls, `tracing`, error or diagnostic text, and REPL rendering of non-graph Rhai values. Any text written to files, visualizer output or script values comes from `value/physical.rs` (`lower`, `write_json`, `to_json_text`).
15. **Additive changes must not break downstream code.** Every public enum is `#[non_exhaustive]` unless its variant set is closed by definition (`Column`, `ElementKind`, `GraphNodeType`); then its doc comment says why. Named-field error variants are `#[non_exhaustive]` as well, so a field can be added later. Public result/config structs with `pub` fields are `#[non_exhaustive]` (`MemoryStats`, the profiling structs, `RenderOptions`, `RenderedOutput`, `Truncation`, `StepFrame`); if callers must create one, give it a constructor or builder. A new `GraphStorage` trait method always has a default implementation. The payload of a new value type's variant is our own type (like `ElementProperty::Uuid(u128)`), never a third-party type such as `chrono::NaiveDate`; conversions to third-party types are `From` impls behind a feature. Inside `graphersal`, `match`es on these enums stay exhaustive, with no `_ =>` arm, so a new variant forces every internal site to be updated. Other workspace crates and `crates/graphersal/tests/` are downstream: they use `_` arms and `..` patterns.
16. **Keep the TinkerPop baseline current.** When a step is added or fixed, run the TinkerPop suite (`--test tinkerpop_features`) and remove the scenarios that now pass from `crates/graphersal/tests/tinkerpop/baseline.toml` in the same change (or regenerate it with `TINKERPOP_UPDATE_BASELINE=1` and review the diff like code). The suite fails on stale entries anyway; the point is that progress is recorded with the change that made it, and a scenario that passes once is protected from regressing from then on.
17. **One integration-test binary.** Every `graphersal` integration test lives in `crates/graphersal/tests/all/<name>.rs`, registered as `mod <name>;` in `tests/all/main.rs` (a feature-gated file keeps its `#![cfg(feature = ..)]` at its own top). Never add a new top-level `tests/*.rs` target: each one is another link and another first-run scan (the full run took 7+ minutes with ~60 binaries). The only exception is `tinkerpop_features.rs` (own process: parallel lanes, panic hook, report). Name files `<topic>_tests.rs`, run a module with `--test all <name>::` (trailing `::`, so a prefix does not match other modules). Keep process-global state (`set_var`, `#[global_allocator]`, a global tracing subscriber, panic hooks, current directory) out of `tests/all/`: a test that needs it becomes a second separate target, listed as an exception with its reason in the `main.rs` header.
18. **Document every deliberate deviation from TinkerPop in three places:** the `///` of the item, the dedicated mdBook page of the feature, and `book/src/for_developers/tinkerpop_deviations.md`. A deviation comes from a user decision, never from convenience.
19. **Keep the compliance page in sync.** Never hand-edit a generated block of `tinkerpop_compliance.md`; regenerate with `TINKERPOP_UPDATE_BASELINE=1` and commit the page together with the baseline when a step moves the number (the page has no hand-written history: the git log is the record) (rule 16 covers the page too).
20. **New traverser constructors say whether the traverser is generated or derived.** Generated (a start step or reducing barrier): `Traverser::start(context, v)`, initial sack. Derived: `split`/`with_parts(.., source.sack)`, keeps the parent's sack and bulk. `size_of::<Traverser>()` stays 80.
21. **No runtime rule struct in the merge hot path.** Never put a runtime rule or option struct into `MergeKey::of` or the merge loop; use const generics as `merge_inner::<S, OPERATOR, ONE>` does (a runtime struct measured +25 % there). When touching `bulk.rs` or `Traverser`, check `cargo bench -p graphersal --bench graph --features io,script,display,serde` (no-sack paths within 5 %).
22. **Creation parameters have one documentation place.** A store parameter that is set when the store is created and never changes (today: the store id, the damage policy, the chunk size, the creation time, the backend and its container version, the format version) goes into the table of `book/src/persistence/creation_parameters.md` (default, how to set it in Rust/CLI/Python/dev server, where it is stored with its format spec section, what copies carry it) and into `graphersal store info`'s "fixed at creation" block and `StoreInfo`; it is never changed by an open (`StoreOptions` setters for it apply to create only), and every copy path (fork, attic fork, repair, convert, backup, restore) carries it, with a test that tries every path. Per-open options are listed separately on the same page.
